# ระบบบันทึก BOM (BOM Data Entry)

เว็บแอปสำหรับกรอกข้อมูล BOM (Bill of Materials) แทนไฟล์ Excel เดิม ใช้งานง่ายกว่าเดิมด้วย:

- **ช่องค้นหาแบบ Combobox** (พิมพ์เพื่อค้นหา + เลือกจากรายการ + เพิ่มรายการใหม่ได้ทันที) สำหรับ ชื่อลูกค้า, รุ่นสินค้า, รหัส Packaging, เฉดสี และรหัสวัตถุดิบ
- **ตัวสร้างรหัส ITEM อัตโนมัติ** จากรูปแบบเดิม เช่น `First-GC-23/P(P)-Y` → รุ่นสินค้า + `(รหัส Packaging)` + `-เฉดสี`
- **หนึ่งคำสั่งผลิตสั่งได้หลาย Item** กรอกบรรทัดละ Item (เห็นทุก Item ในสายตาเดียว) แต่ละ Item มีจำนวนสั่งและตารางวัตถุดิบของตัวเอง แล้วกด "โหลดสูตรวัตถุดิบทุก Item" ที่จุดเดียวใต้รายการครั้งเดียวเพื่อดึงสูตรเดิมและคำนวณให้ทุก Item พร้อมกัน
- **กำหนดเริ่ม-เสร็จรายแผนก** (RB, GR, PT, BG, PK, ST) ในตัวคำสั่งผลิต
- **โหลดสูตรวัตถุดิบจากระบบเดิมอัตโนมัติ** ถ้ารหัส ITEM เคยมีอยู่ในไฟล์ MRP เดิม (นำเข้าไว้แล้ว 28,697 แถว จาก 1,153 สินค้า)
- **คำนวณจำนวนที่ต้องเบิก/สั่งซื้อ** อัตโนมัติจาก จำนวนสั่งของ Item นั้น × จำนวนใช้ต่อ 1 FG − คงคลัง พร้อม **ตารางสรุปรวมวัตถุดิบทั้งคำสั่ง** (วัตถุดิบเดียวกันที่ใช้หลาย Item ถูกบวกรวมให้)
- **ข้อมูลบันทึกลง Google Sheet ของคุณโดยตรง** ผ่าน Google Apps Script (ไม่ต้องมี Service Account หรือ credential ใด ๆ)
- **ประวัติการบันทึก** ค้นหาย้อนหลัง และ "ใช้เป็นแบบร่างใหม่" เพื่อคัดลอกรายการเดิมได้ทันที

โครงสร้างโปรเจกต์:

```
apps-script/   Google Apps Script backend (ผูกกับ Google Sheet) — ไฟล์เดียวคือ Code.gs
docs/          เว็บแอป (static, ไม่ต้อง build) — index.html, app.js, styles.css
               (ชื่อโฟลเดอร์ต้องเป็น docs/ เพราะ GitHub Pages รองรับเฉพาะ / หรือ /docs)
  data/          ข้อมูลอ้างอิงที่เว็บอ่านตรง ๆ (สร้างด้วย scripts/build_web_data.py)
data/          ไฟล์ JSON ข้อมูลอ้างอิงต้นทาง (ดึงมาจากไฟล์ MRP Excel)
scripts/       extract.py = Excel → data/*.json, build_web_data.py = data/ → docs/data/
```

### ข้อมูลไหลอย่างไร

- **ข้อมูลอ้างอิง** (รายการสินค้า, วัตถุดิบ, สูตร BOM เดิม, รหัส Packaging/เฉดสี) → เว็บอ่านจากไฟล์ใน `docs/data/` **โดยตรง ไม่ผ่าน Google Sheet** ทำให้เร็วและไม่พังเวลา Apps Script มีปัญหา (สูตรวัตถุดิบแยกเป็นไฟล์ละสินค้า เว็บโหลดเฉพาะไฟล์ที่ต้องใช้ ~10KB ไม่ใช่ทั้งก้อน 15MB)
- **ข้อมูลที่บันทึก** (คำสั่งผลิต + รายการวัตถุดิบ) → เขียนลง **Google Sheet** ผ่าน Apps Script ตามที่ต้องการ
- **ประวัติการบันทึก** → อ่านกลับจาก Google Sheet

ผลคือ ถ้า Apps Script มีปัญหา จะยังกรอกข้อมูลและโหลดสูตรได้ตามปกติ แค่กดบันทึกไม่ได้เท่านั้น

## ขั้นตอนที่ 1 — ตั้งค่า Google Apps Script (ทำครั้งเดียว)

1. เปิด Google Sheet ที่ต้องการใช้เก็บข้อมูล ([ลิงก์ชีทของคุณ](https://docs.google.com/spreadsheets/d/1CvMNe_mv8jUp1rjxRD85xOokNAcPJwKBK6kL46hDcRk/edit))
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเริ่มต้นในไฟล์ `Code.gs` (หรือ `รหัส.gs`) ที่เปิดมาทั้งหมด แล้ววางเนื้อหาทั้งหมดจากไฟล์ [`apps-script/Code.gs`](apps-script/Code.gs) ของโปรเจกต์นี้แทน (ไฟล์เดียวพอ — ไม่ต้องสร้างไฟล์ `SeedData.gs` แยกอีกต่อไป)
4. กด **บันทึก (Ctrl+S / Cmd+S)**
5. ที่แถบด้านบน เลือกฟังก์ชัน **`initializeSheet`** จาก dropdown แล้วกด **Run** (▶) — จะสร้างชีทย่อยทั้งหมด (BOM_Master, Materials_Catalog, FG_Base_Items, Packaging_Codes, Color_Shades, BOM_Orders, BOM_Order_Items, BOM_Order_Lines) พร้อม header แต่ยังไม่มีข้อมูล — **รันซ้ำได้เสมอ ไม่ลบข้อมูลเดิม** (ใช้รันซ้ำเมื่ออัปเดต `Code.gs` แล้วมีชีท/คอลัมน์ใหม่)
   - ครั้งแรกจะมีหน้าต่างขอสิทธิ์ (Authorization required) → กด **Review permissions** → เลือกบัญชี Google ของคุณ → ถ้าเจอหน้าเตือน "Google hasn't verified this app" ให้กด **Advanced** → **Go to (ชื่อโปรเจกต์) (unsafe)** → **Allow**
6. เปลี่ยน dropdown ฟังก์ชันเป็น **`resyncMasterData`** แล้วกด **Run** (▶) อีกครั้ง — ฟังก์ชันนี้จะดึงข้อมูลอ้างอิง (สูตรวัตถุดิบ, คลังวัตถุดิบ, รุ่นสินค้า, รหัส Packaging/เฉดสี) จากไฟล์ในโฟลเดอร์ `data/` ของ repo นี้บน GitHub มาใส่ในชีทให้อัตโนมัติ (ข้อมูลมีขนาดใหญ่ ~15MB อาจใช้เวลาสักครู่ ~30-60 วินาที)
   - ถ้าสำเร็จจะเห็น log ประมาณ: `Synced: 28697 recipe rows, 4318 materials, 1374 base items.`
7. Deploy เป็น Web App: เมนู **Deploy → New deployment**
   - Select type: **Web app**
   - Execute as: **Me (อีเมลของคุณ)**
   - Who has access: **Anyone**
   - กด **Deploy** แล้วคัดลอก **Web app URL** ที่ได้ (ขึ้นต้นด้วย `https://script.google.com/macros/s/.../exec`)

> เก็บลิงก์นี้ไว้ให้ดี ใครก็ตามที่มีลิงก์นี้จะสามารถบันทึกข้อมูลลงชีทได้ — อย่าเผยแพร่ลิงก์นี้แบบสาธารณะ

หากภายหลังแก้ไข `Code.gs` ต้องทำ **Deploy → Manage deployments → แก้ไข (ไอคอนดินสอ) → Version: New version → Deploy** ใหม่ทุกครั้ง ลิงก์ URL จะเหมือนเดิม (แต่ **ไม่ต้อง** deploy ใหม่แค่เพื่อรัน `resyncMasterData` — รันจาก editor ได้ตรง ๆ เสมอ)

### อัปเดตข้อมูลอ้างอิงในภายหลัง

ถ้าข้อมูลในไฟล์ Excel ต้นฉบับเปลี่ยน (เช่น มีสินค้า/วัตถุดิบใหม่) ให้:
1. รัน `scripts/extract.py` จากไฟล์ Excel ฉบับล่าสุด (ได้ `data/*.json`)
2. รัน `scripts/build_web_data.py` (ได้ `docs/data/` ที่เว็บใช้จริง)
3. commit ไฟล์ที่เปลี่ยนขึ้น GitHub — **เว็บจะใช้ข้อมูลใหม่ทันทีที่ GitHub Pages build เสร็จ**
4. (ไม่บังคับ) ถ้าอยากให้สำเนาข้อมูลในชีทอัปเดตตามด้วย ให้รันฟังก์ชัน **`resyncMasterData`** ใน Apps Script editor

`resyncMasterData` จะ **แทนที่ทั้งหมด** ในชีท `BOM_Master` / `Materials_Catalog` / `FG_Base_Items` ด้วยข้อมูลล่าสุดจาก `data/*.json` เสมอ (เพราะถือว่าไฟล์นั้นคือข้อมูลหลัก) ส่วน `Packaging_Codes` / `Color_Shades` จะแค่ **เพิ่มรหัสที่ยังไม่มี** โดยไม่ลบ/ทับคำอธิบายที่กรอกไว้แล้ว และ **`BOM_Orders` / `BOM_Order_Lines` (ข้อมูลคำสั่งผลิตที่บันทึกจริง) จะไม่ถูกแตะต้องเด็ดขาด**

## ขั้นตอนที่ 2 — เปิดใช้งานเว็บแอป

โฟลเดอร์ `docs/` เป็นเว็บไซต์ static ธรรมดา (HTML/CSS/JS) ไม่ต้อง build ไม่ต้องมีเซิร์ฟเวอร์พิเศษ เลือกวิธีใดวิธีหนึ่ง:

- **GitHub Pages** (แนะนำ ฟรี): ใน repo settings → Pages → Deploy from branch → เลือก branch นี้และโฟลเดอร์ `/docs`
- **เปิดจากเครื่อง**: ดับเบิลคลิกไฟล์ `docs/index.html` ได้เลย (บางเบราว์เซอร์อาจบล็อก fetch จากไฟล์ local — ถ้าเจอปัญหาให้รันเซิร์ฟเวอร์เล็ก ๆ เช่น `npx http-server docs`)
- **Netlify / Vercel**: ลาก-วางโฟลเดอร์ `docs/` เพื่อ deploy ได้ทันที

เว็บถูกตั้งค่าให้เชื่อมต่อ Apps Script Web App ที่ deploy ไว้แล้วโดยอัตโนมัติ (ฝังลิงก์ไว้ในโค้ดแล้ว) — ถ้าต้องการเปลี่ยนไปใช้ Apps Script คนละตัว ไปที่แท็บ **"การเชื่อมต่อ"** แล้ววางลิงก์ Web App URL ใหม่ได้ที่นั่น (จะถูกจำไว้ในเบราว์เซอร์นั้น ๆ แทนค่าเริ่มต้น)

## วิธีใช้งาน

### สร้าง BOM ใหม่

หน้าจอเรียงตามลำดับการกรอกจริง 5 หัวข้อ: **ข้อมูลคำสั่งผลิต → กำหนดเริ่ม-เสร็จของแต่ละแผนก → รหัสสินค้า (ITEM) → รายการวัตถุดิบแต่ละ Item → สรุปวัตถุดิบรวม**

1. **ข้อมูลคำสั่งผลิต** — ช่อง "ลูกค้า" เป็นแบบ **ค้นหา + dropdown** (รายชื่อลูกค้าดึงจากคำสั่งผลิตที่เคยบันทึกไว้ในชีท ถ้าเป็นลูกค้าใหม่พิมพ์ชื่อลงไปแล้วเลือก "+ ใช้ชื่อลูกค้าใหม่" ได้ทันที) นอกนั้นกรอก เลขที่คำสั่งซื้อ/PI, วันที่สั่งผลิต, กำหนดส่งมอบ และหมายเหตุ
   - **จำนวนที่สั่งไม่ได้อยู่ตรงนี้แล้ว** — ย้ายไปกรอกรายตัวสินค้าในหัวข้อ 3 เพราะหนึ่งคำสั่งผลิตสั่งได้หลาย Item ที่จำนวนต่างกัน
2. **กำหนดเริ่ม-เสร็จของแต่ละแผนก** — ตารางวันเริ่ม/วันเสร็จของ 6 แผนกตามลำดับสายการผลิต: **RB, GR, PT, BG, PK, ST** (แผนกที่ไม่เกี่ยวข้องกับคำสั่งผลิตนี้เว้นว่างไว้ได้)
3. **รหัสสินค้า (ITEM)** — **หนึ่งบรรทัด = หนึ่ง Item** เลือก รุ่นสินค้า + Packaging + เฉดสี แล้วใส่ **จำนวนที่สั่งต่อท้าย** ในช่องสุดท้ายของบรรทัดเดียวกัน ทุก Item อยู่ในสายตาเดียวตรวจทานได้ง่าย
   - พิมพ์ค้นหารุ่นสินค้าในช่องแรก ถ้าไม่มีในรายการ พิมพ์ชื่อใหม่แล้วเลือก "+ เพิ่มรุ่นสินค้าใหม่" ได้ทันที ทำแบบเดียวกันกับช่อง Packaging และเฉดสี
   - รหัส Packaging (พบ 9 แบบในข้อมูลเดิม: `B`,`C`,`P`,`BN`,`X`,`N`,`F`,`BC`,`K`) จะถูกใส่ในวงเล็บ เช่น `(P)`
   - เฉดสี (พบ 16 แบบในข้อมูลเดิม: `A`,`B`,`C`,`D`,`E`,`F`,`G`,`H`,`I`,`O`,`P`,`P1`,`P2`,`P3`,`Y`,`Z`) ยังไม่มีคำอธิบายในระบบ — **สามารถเพิ่มคำอธิบายภายหลังได้** โดยพิมพ์เพิ่มในช่อง "เฉดสี" ของเว็บ หรือเปิดชีท `Color_Shades` แล้วกรอกคอลัมน์ DESCRIPTION เพิ่มเองได้โดยตรง
   - ถ้าต้องการพิมพ์รหัส ITEM แบบเต็มเอง กดปุ่ม **✎** ท้ายบรรทัดนั้น (กดซ้ำเพื่อกลับไปเลือกจากรายการ)
   - กด **"+ เพิ่ม Item"** ใต้รายการเพื่อต่อบรรทัดลงมาเรื่อย ๆ
4. เมื่อครบทุก Item แล้วกด **"โหลดสูตรวัตถุดิบทุก Item"** — ปุ่มนี้มี **จุดเดียว อยู่ล่างสุดของหัวข้อ 3** ถัดจากปุ่มเพิ่ม Item กดครั้งเดียวระบบจะดึงสูตรเดิมของ **ทุก Item พร้อมกัน** และคำนวณให้ทันที ผลของแต่ละ Item ("โหลดสูตรเดิมแล้ว N รายการ" / "ไม่พบสูตรเดิม") จะขึ้นใต้บรรทัดของ Item นั้น พร้อมสรุปรวมข้างปุ่ม
   - ถ้าไม่เจอรหัสเต็ม จะถอยไปหาสูตรของ "รุ่นสินค้า" ให้แทน แล้วบอกไว้ในข้อความว่าดึงมาจากรุ่นไหน — เลียนแบบการทำงานของมาโคร `add_Item` ในไฟล์ Excel เดิม (รวมถึงหน่วยวัสดุที่ดึงจากคอลัมน์ "หน่วยนับ RB" เหมือนกัน)
5. **รายการวัตถุดิบแต่ละ Item** (หัวข้อ 4) — แก้ไข/เพิ่ม/ลบได้อิสระ ค้นหารหัสวัตถุดิบจากคลังเดิม (4,318 รายการ) หรือเพิ่มรหัสใหม่ได้ทันที กดหัวข้อของ Item เพื่อย่อ/ขยายตารางได้ ตัวเลข "ต้องเบิก/สั่งซื้อ" คิดจาก จำนวนใช้ต่อ 1 FG × **จำนวนที่สั่งของ Item นั้น** − คงคลัง
6. **สรุปวัตถุดิบรวมทั้งคำสั่งผลิต** (หัวข้อ 5) รวมความต้องการของทุก Item เข้าด้วยกัน — วัตถุดิบรหัสเดียวกันที่ใช้หลาย Item จะถูกบวกรวมเป็นยอดเดียวสำหรับสั่งซื้อ
7. กด **"บันทึกลง Google Sheet"**

### ประวัติการบันทึก

ดูรายการที่เคยบันทึกทั้งหมด ค้นหาด้วยรหัส ITEM/ลูกค้า และกด **"ใช้เป็นแบบร่างใหม่"** เพื่อคัดลอกรายการเดิมมาปรับแก้เป็นคำสั่งผลิตใหม่ได้ทันที

## โครงสร้างข้อมูลใน Google Sheet

| ชีท | เนื้อหา |
|---|---|
| `BOM_Master` | สูตรวัตถุดิบมาตรฐานเดิมทั้งหมด (28,697 แถว จากไฟล์ MRP ฉบับเต็ม) ใช้เป็นฐานสำหรับ "โหลดสูตรจากระบบเดิม" — เว็บดึงเฉพาะแถวที่ตรงกับ ITEM ที่ค้นหาเท่านั้น ไม่ได้โหลดทั้งหมดมาไว้ล่วงหน้า |
| `Materials_Catalog` | รายชื่อวัตถุดิบทั้งหมดแบบไม่ซ้ำ (4,318 รายการ) ใช้เป็นตัวเลือกค้นหาในฟอร์ม |
| `FG_Base_Items` | รายชื่อรหัสสินค้า/รุ่นสินค้าที่เคยใช้ (1,374 รายการ) |
| `Packaging_Codes` | รหัส Packaging + คำอธิบาย (กรอกเพิ่มเองได้) |
| `Color_Shades` | รหัสเฉดสี + คำอธิบาย (**ยังว่าง รอกรอกเพิ่มภายหลังตามที่แจ้งไว้**) |
| `BOM_Orders` | หัวรายการ BOM ที่บันทึกจากเว็บแต่ละครั้ง (1 แถว = 1 คำสั่งผลิต) — ลูกค้า, เลขที่ PI, วันที่, และ **กำหนดเริ่ม-เสร็จของแต่ละแผนก** (`RB_START`/`RB_END`, `GR_START`/`GR_END`, `PT_*`, `BG_*`, `PK_*`, `ST_*`) ส่วนคอลัมน์ `ITEM` / `ORDER_QTY` เป็นยอดรวมของทั้งคำสั่ง (รหัส Item ทุกตัวต่อกัน และผลรวมจำนวนสั่ง) |
| `BOM_Order_Items` | Item ที่สั่งในคำสั่งผลิตนั้น 1 แถว = 1 Item พร้อมจำนวนที่สั่งของตัวเอง (อ้างอิงกลับด้วย `ORDER_ID` + `ITEM_NO`) |
| `BOM_Order_Lines` | รายการวัตถุดิบของแต่ละ Item (อ้างอิงกลับด้วย `ORDER_ID` + `ITEM_NO`) |

> คำสั่งผลิตที่บันทึกไว้ด้วยเวอร์ชันก่อนหน้า (แบบ 1 คำสั่ง = 1 Item ไม่มีแถวใน `BOM_Order_Items`) ยังอ่านได้ตามปกติในหน้า "ประวัติการบันทึก" — ระบบจะมองเป็นคำสั่งที่มี Item เดียว
>
> ถ้าเคยรัน `initializeSheet` ไปแล้วก่อนหน้านี้ ให้**รัน `initializeSheet` ซ้ำอีกครั้ง** หลังอัปเดต `Code.gs` เพื่อสร้างชีท `BOM_Order_Items` และเพิ่มคอลัมน์ใหม่ใน `BOM_Orders` / `BOM_Order_Lines` (ข้อมูลเดิมไม่ถูกลบ) แล้ว **Deploy → Manage deployments → New version** เพื่อให้เว็บดึงรายชื่อลูกค้าและบันทึกแบบหลาย Item ได้

## หมายเหตุด้านข้อมูล

- ข้อมูล `BOM_Master`/`Materials_Catalog`/`FG_Base_Items` แปลงมาจากชีท `DATA` ในไฟล์ **`Material_MP_MRP_41_Ver_Toy.xlsm`** (ไฟล์ฉบับเต็มที่ยึดเป็นหลัก) — 1,153 รหัสสินค้า, 28,697 แถวสูตรวัตถุดิบ, วัตถุดิบไม่ซ้ำ 4,318 รายการ
- รูปแบบรหัส ITEM (`ฐาน(Packaging)-เฉดสี`) วิเคราะห์จากรูปแบบชื่อที่พบทั่วทั้งไฟล์ (ไม่ใช่แค่ตัวอย่างไฟล์คำสั่งผลิตเดียว) พบรหัส Packaging 9 แบบ และรหัสเฉดสี 16 แบบ — **ความหมายของแต่ละรหัสยังไม่ทราบแน่ชัดจากไฟล์ต้นฉบับ** จึงเว้นช่องคำอธิบายไว้ให้กรอกเพิ่มเติมเองในชีท `Packaging_Codes` / `Color_Shades` หรือผ่านเว็บแอปได้เลย
